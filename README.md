# AL AZM GLOBAL REAL ESTATE

المستودع الرسمي للموقع ومنظومة العمليات الرقمية لشركة العزم العالمية للعقارات.

## الملفات الأساسية

- `index.html`: الموقع التعريفي العام ونموذج استقبال الطلبات.
- `properties.html`: كتالوج عام يعرض العقارات المنشورة فقط ويتيح البحث والتصفية.
- `privacy.html`: بيان خصوصية بيانات العملاء.
- `login.html`: تسجيل دخول الإدارة عبر Supabase Auth.
- `admin-cloud.html`: لوحة العمليات السحابية للعقارات والمصادر وطلبات العملاء ومهام الذكاء الاصطناعي.
- `admin.html`: نموذج إدارة محلي تجريبي قديم؛ لا تستخدمه كلوحة الإنتاج.
- `employees-cloud.html`: واجهة الفريق السحابي.
- `employee-profiles.html`: بطاقات تعريفية للأدوار الرقمية الاثني عشر المسجلة في قاعدة البيانات؛ ليست سيراً ذاتية لأشخاص أو دليلاً على تشغيل مستقل.
- `api/ai-tasks.js`: واجهة خادم لإدارة مهام الذكاء الاصطناعي.
- `api/run-task.js`: تشغيل مهام التقارير المحدودة عبر Gemini مع مهلة زمنية وسجل تدقيق.
- `api/public-lead.js`: استقبال طلبات الموقع العامة وحفظها في جدول العملاء عبر مفتاح خادمي غير مكشوف للمتصفح.
- `supabase/migrations/`: مخططات قاعدة البيانات وسياسات الوصول والحماية.

## ما تم إنجازه والتحقق منه

- المستودع عام والفرع الأساسي هو `main`.
- الموقع منشور على Vercel Production، والنطاق الأساسي: https://alazm-global-real-estate.vercel.app/
- تم إثبات ملكية الموقع في Google Search Console وإضافة بيانات SEO وملف sitemap وrobots.
- تم إعداد مخطط Supabase وجداول العقارات والمصادر والعملاء وسجل التدقيق وموظفي الذكاء الاصطناعي.
- نجح تشغيل GitHub Actions رقم 15 بتاريخ 2026-11-21، وكانت خطوة baseline متجاوزة، ثم اكتملت خطوة `supabase db push` بنجاح لتطبيق الترحيلات المعلقة.
- توجد متغيرات الإنتاج في Vercel: `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` و`GEMINI_API_KEY`. لا تضع القيم السرية في هذا المستودع.
- تم تفعيل 12 دوراً على محول Gemini واحد محدود لإعداد التقارير فقط؛ لا تمثل هذه الأدوار وكلاء مستقلة، ولا تملك تصفحاً أو نشراً أو تواصلاً خارجياً أو اعتماداً ذاتياً.

## حدود التشغيل الحالية

- نجاح نشر Vercel يثبت اكتمال عملية النشر، لكنه لا يثبت وحده نجاح تسجيل الدخول أو كل عمليات قاعدة البيانات من واجهة المستخدم.
- يلزم اختبار حساب مالك نشط في Supabase Auth وصفحتي `login.html` و`admin-cloud.html`.
- جميع الأدوار الـ12 مفعّلة لإنتاج تقارير داخلية عبر محول مشترك ومحدود؛ كل النتائج تبقى `needs_review` وتتطلب موافقة بشرية، ولا توجد وكلاء مستقلة أو تكاملات تنفيذية خارجية.
- نموذج طلب الموقع العام يحفظ الطلب في `public.leads` بعد موافقة العميل، ويتحقق الخادم من المدخلات ويستخدم مفتاح Supabase الخادمي فقط. توجد صفحة سياسة خصوصية مرتبطة بموافقة النموذج. يوجد حد إرسال مؤقت داخل مثيل الوظيفة وحقل honeypot؛ يلزم لاحقاً إضافة حماية CAPTCHA أو حد مركزي دائم قبل الحمل العام الكبير.
- يوجد كتالوج عام متصل بقاعدة البيانات يعرض العقارات بحالة `published` فقط؛ لا يوجد حتى الآن تكامل جمع آلي لمصادر العقارات.
- لا يوجد نشر تلقائي للعقارات إلى مواقع أو منصات خارجية.
- بيانات الدخول ومفاتيح الخادم لا يجوز وضعها في ملفات الواجهة أو GitHub.


## حالة الجاهزية التشغيلية — 23 نوفمبر 2026

هذه الحالة مبنية على فحص قاعدة البيانات والملفات البرمجية، وليست شهادة تشغيل تجاري أو قانوني:

- حساب مالك نشط واحد موجود في `public.profiles`؛ لم يتم اختبار تسجيل الدخول بجلسة المالك من المتصفح في هذا الفحص.
- 12 دوراً رقمياً مسجلاً ومفعّلاً في `public.ai_employees`، وكلها تتطلب موافقة بشرية. لا يعني تفعيل السجل أن كل دور يعمل كوكيل مستقل.
- قاعدة البيانات حالياً: 0 عقارات، 0 طلبات عملاء، 0 مصادر. لا توجد بيانات تجارية فعلية يمكن عرضها في الكتالوج بعد.
- توجد 4 مهام تاريخية: مهمة واحدة في الطابور، تقريران بانتظار مراجعة المالك، ومهمة فاشلة. لم تتم إعادة تشغيل أو اعتماد أي منها خلال الفحص.
- يوجد مسار تجهيز عقار واحد من 6 مراحل؛ المرحلة الأولى queued والخمس التالية blocked حتى اعتماد المرحلة السابقة.
- تشغيل Gemini محمي بشرط `GEMINI_FREE_TIER_CONFIRMED=true`، ويجب عدم تغييره قبل إثبات أن المفتاح والحساب على حصة مجانية مع تعطيل الفوترة وموافقة المالك.
- لا يوجد جمع آلي لمصادر العقارات، ولا نشر خارجي تلقائي، ولا تواصل آلي مع العملاء. نشر الموقع العام يعرض فقط السجلات التي تجتاز شروط النشر في قاعدة البيانات.
- استقبال طلبات العملاء العام يتطلب اختباراً حقيقياً مصرحاً به بعد مراجعة سياسة الخصوصية والحماية من الرسائل المزعجة؛ لم يُنشأ طلب تجريبي في قاعدة البيانات.
- تنبيه Supabase الأمني الحالي: حماية كلمات المرور المسربة غير مفعّلة. يتطلب تفعيلها خطة تدعم الميزة؛ لا تتم ترقية الخطة دون موافقة المالك.
- سجلات Vercel وبيانات الحصة لم تكن قابلة للقراءة من اتصال الأدوات بسبب رفض الصلاحية 403؛ لا نستنتج من ذلك أن الحصة ممتلئة أو خالية.

راجع [دليل الجاهزية والتشغيل](OPERATIONS_READINESS.md) لقائمة اختبارات ما قبل استقبال العملاء.

## الخطوات التالية قبل التشغيل التجاري

1. تأكيد وجود حساب المالك في Supabase Auth.
2. التحقق من UUID للحساب الصحيح، ثم التأكد من أن دوره `owner` وأن `active = true` في `public.profiles`.
3. تسجيل الدخول إلى `/login.html` واختبار لوحة `/admin-cloud.html`.
4. اختبار إرسال طلب تجريبي من الموقع والتحقق من ظهوره في لوحة الإدارة وقاعدة البيانات، دون استخدام بيانات عميل حقيقية أثناء الاختبار.
5. اختبار إضافة مصدر وعقار بحساب المالك، ثم التحقق من ظهور السجلات في قاعدة البيانات.
6. تشغيل مهمة اختبار واحدة للمدير التنفيذي الذكي والتحقق من حفظ التقرير وسجل التشغيل.
7. اختبار صلاحيات المستخدمين المختلفين وRLS قبل دعوة أي موظف أو فتح النظام للجمهور.
8. بناء كتالوج العقارات العام ومحرك البحث، وإضافة CAPTCHA وحد إرسال مركزي لطلبات العملاء قبل الحمل العام الكبير.
9. بناء تكاملات مصادر العقارات فقط وفق موافقات الملاك وشروط الاستخدام وحقوق إعادة النشر.

## سياسة النشر والحقوق

لا يُنشر أي عقار إلا بعد توثيق مصدره ووجود إذن صريح ونطاق استخدام واضح واكتمال البيانات واجتياز فحوص التكرار والاشتباه. تُحال الحالات الناقصة أو المشبوهة للمراجعة البشرية. لا يُسمح للذكاء الاصطناعي باتخاذ قرارات قانونية أو مالية أو نشر خارجي دون موافقة مخوّلة.

## إعدادات Vercel

تحتاج وظائف الخادم إلى متغيرات إنتاج سرية:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` (خادمي فقط)
- `GEMINI_API_KEY` (خادمي فقط)

المفتاح المنشور في `supabase-config.js` هو Publishable Key، وهو مخصص للواجهة العامة وتظل صلاحياته محكومة بسياسات RLS. لا تستخدم Secret Key أو Service Role Key في المتصفح مطلقاً.
